# CT 119からの安全な移行

**移行完了条件は新WOLサーバーから対象実機が起動すること。旧CT 119はそれまで削除しない。** 旧CTはUbuntu 23.04でありサポート終了のため、旧環境を直接アップグレードせずUbuntu 24.04へ並行移設する。

## 旧アプリとの対応

| 旧 | 新 |
|---|---|
| `$pc_list` の `hostname`, `ip`, `mac` | SQLite登録。画面から追加・編集できる |
| 固定 /24 の末尾255変換 | 設定されたCIDRからブロードキャストアドレスを計算 |
| `broadcast`, `unicast`, `both` | 選択可能。各宛先へ2パケット |
| `mac` 名称の255.255.255.255送信 | 廃止。L2 MACユニキャスト機能ではなかったため。必要なら明示的なbroadcastとVLANルーティングを使用 |
| Webルート内テキストログとログ削除 | Webルート外SQLite履歴、Webから削除可能 |
| 認証なし・CSRFなし | 認証なし（LAN限定の明示的要件）、CSRFあり |

## 機器登録の移行

1. 旧CT `/var/www/html/wol/config.php` の**秘密バックアップ**を作成。GitHub・チャットにはアップロードしない。
2. 新環境で`config/local.php`にLAN情報を記載。対象PCがどちらのネットワークに属するかを確認。
3. 画面から個別に追加、または信頼できる旧 `config.php` を非公開ディレクトリに移してCLIで以下を実行。

```bash
# 旧config.phpは任意のPHPコードとして実行されるため、必ず信頼できる原本に限る
sudo -u www-data php8.3 /var/www/wol-webui/bin/import-legacy.php /secure/location/config.php
```

`www-data` に旧設定を読ませる必要があるため、アクセス権は一時的に適切に設定し、移行後は元に戻すこと。旧PC一覧の`hostname`, `ip`, `mac`を読み、`ip`が**設定CIDRの一つだけ**に属する機器を登録。MACの一致で重複はスキップし、既存機器は変更しない。未登録の対象やIP不一致はUIから手動登録する。旧ログは自動移行しない（保存する場合は別途秘密アーカイブとして保全）。

## ロールバックと検証

- 旧CTと新CTは並行運用可能。新CTで起動失敗した場合は旧CTから起動できるか検証し、ネットワーク差異を記録。
- 送信ログ成功は実機の起動成功ではない。**各VLAN、各機器、Tailscale経由UI**を含めて検証。
- 新サーバーのDBと設定バックアップを作成し、旧CT停止を試してから、削除は別操作として判断。
